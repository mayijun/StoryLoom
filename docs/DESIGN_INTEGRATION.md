# StoryLoom 设计整合与外部参考评估

> 目的：把分散的设计讨论与 `docs/` 里的结论收敛成一套判断标准，
> 明确外部参考中哪些做法值得吸收、哪些不适用于我们的产品，并给出模板 / 案例故事的适配要求。
>
> 本文是**取舍依据**，不替代各专项文档；具体接口与实现仍以代码和 ARCHITECTURE.md 为准。

---

## 0. 一句话结论

StoryLoom 是**作者工作台 + 世界运行时**，不是内容市场，也不是角色卡聊天室。
值得吸收的是「世界先于主角、NPC 自主、后果驱动、状态可见、开放行动」这一组叙事机制；
不适用于我们的是作品广场、付费/角色卡市场、暖色门户、伪数值状态栏和顺从玩家的单 Agent 行为。

---

## 1. 设计依据整合

| 设计主题 | 整合后的定位 |
|---|---|
| 章节 / 场景 / 写作工作台 | **前端主界面的唯一实现依据**：项目 → 章节 → 场景 → 正文 |
| 写作与返修体验 | 前端 P0/P1/P2 的缺陷对策来源 |
| 平台化与商业化边界 | 明确「作品广场 / 付费 / 账号」不在 StoryLoom 内 |
| 双模式 Flow | 游戏模式是同一运行时的另一种输入，不是第二套前端 |
| 架构与运行时 | 所有 UI 与模板都必须服从 [ARCHITECTURE.md](ARCHITECTURE.md) 的约束 |
| 当前能力与验收 | 只承诺已实现或明确排期的能力，见 [MVP.md](MVP.md) / [TECHNICAL.md](TECHNICAL.md) |
| 仙侠样板验收 | 模板改写后的验收剧本见 [DEMO_XIANXIA_SYSTEM.md](DEMO_XIANXIA_SYSTEM.md) |

整合后的前端只有两个工作区：

1. **作者工作台**（默认）：章节树、场景正文、资产、Agent/Task 配置、导出。
2. **游戏模式 overlay**：对话、选项、世界状态/世界书、存档；退出即回到作者工作台。

不新增作品广场、作者主页、角色卡市场、独立游戏大厅。这些属于未来平台项目，不属于 StoryLoom。

---

## 2. 我们的设计边界

结合统一前端设计与平台边界的讨论，本轮再次确认：

- **内容优先**：写作区占视觉中心，配置与游戏模式为辅助。
- **双模式共用资产**：作者模式与游戏模式共享项目、角色、地点、伏笔、章节与记忆。
- **单一事实源**：`WorldState` 是运行时事实；`Fact / Belief / Memory` 分层；LLM 只能提案。
- **AI 产出是草稿**：生成只是起点，返修、对比、回滚是核心能力。
- **扩展只挂在钩子上**：模板通过 `skill / mod` 提供文风与地图，不改核心流程。
- **不新增前端依赖**：继续使用现有 Vue + 原生 DnD + CSS 变量。
- **暗色、数据密集、工具感**：保留现有 `--bg-primary / --border / --accent` 体系。

## 3. 外部参考评估

### 3.1 值得借鉴

| 外部参考的做法 | 为什么值得 | StoryLoom 的落法 |
|---|---|---|
| 世界模拟优先，NPC 有自主目标 | 这是「活世界」的核心，也是单 Agent 顺从问题的解药 | 已在 `NarrativeEngine` 的 `_npc_round_fallback` / `SceneCrew.npc_actions` 中存在；模板文案强化 NPC 各自有账 |
| 选择有真实后果 | 玩家输入不能总被奖励 | 裁决可失败、可被拦截；模板把「签到」改成有代价的契约 |
| 状态栏 / 世界书 | 让玩家看见世界，而不是只听旁白 | 游戏面板保留「世界状态 / 世界书」，新增节拍、在场角色、标记与关系 |
| 开放式文本输入 + 选项并存 | 兼顾自由与可玩性 | 自由文本直接进回合链；选项是 Agent JSON 里的 `choices`，只作快捷输入 |
| 开场用「世界卡」交代角色与处境 | 降低进入成本 | 模板的 `description + 角色 + 地点 + 章节大纲` 就是世界卡；渲染时注入作品设定 |
| 明确「世界不会围着你转」 | 管理玩家预期 | 渲染 prompt 与模板 skill 都写明这条约束 |

### 3.2 不值得借鉴

| 外部参考的做法 | 为什么不借鉴 |
|---|---|
| 作品广场、卡片流、作者主页 | 那是平台内容分发，不是 StoryLoom 的运行时；`platform_design_plan.md` 已划到另 repo |
| 付费、订阅、收藏、角色卡市场 | 商业化与账号体系不在 StoryLoom 范围 |
| 暖色 / 编辑风门户界面 | 与现有暗色作者工作台冲突；游戏模式应是 overlay，不是第二个站点 |
| 华丽但未实现的金钱 / 好感 / 名声数值 | 会制造伪状态；我们只显示 `WorldState` 里真实存在的字段 |
| 游戏内重复多步创建世界 / 角色 | 资产属于作者工作台；游戏模式只消费，不重复创建 |
| 18+ / 破甲内容 | 不做 |
| 单 Agent 顺从玩家、自动让玩家赢 | 与「导演 Agent 裁决 + 世界先于主角」直接冲突；必须避免 |

## 4. 前端映射（只做克制增强）

保留现有页面结构，不重做视觉系统。本轮只把「世界可见」这一原则落到已有位置：

- **游戏状态栏**：继续显示模式 / 回合 / 地点 / 在场角色。
- **世界状态 tab**：在原有时间、回合、质量、等待之后，增加
  - 叙事节拍（起 / 承 / 转 / 合、张力目标、剩余节拍）；
  - 在场角色（情绪、HP）；
  - 世界标记 `flags` 与关系 `relationships`。
- **对话流**：narrator 条目下增加舞台指令 chip（移动 / 场景 / 受阻），不改变正文。
- **行动选项**：增加序号与动作类型标签，便于快速识别。
- **世界书 tab**：继续按重要度展示 `archive` 条目；不新增市场式收藏。

明确不做：作品广场、付费入口、角色卡商店、暖色主题、独立游戏大厅、伪数值条。

## 5. 模板 / 案例故事的适配要求

模板不是「设定集」，而是**世界运行时的初始条件**。要适配 StoryLoom 的设计，模板必须满足：

1. **每个角色都有独立动机**：至少一个目标与玩家无关；NPC 不因玩家一句话就改立场。
2. **主角没有免费外挂**：能力必须带代价（时间、记忆、人情、债、暴露风险）。
3. **伏笔只写「可见线索」**：`description` 能被角色看见；`target_revelation` 只给导演 Agent，不直接进渲染。
4. **章节大纲写「处境」而不是「爽点」**：每章结束留下可被行动回应的具体问题。
5. **文风 skill 反爽文、反越权**：不替玩家做决定，不自动胜利，不让 NPC 无条件臣服。
6. **地点与路线服务于后果**：移动有耗时，地点有各自的规则与目击者。
7. **世界书不泄露秘密**：运行时注入角色动机、地点、活跃伏笔描述，不注入 `secrets` 与 `target_revelation`。

### 5.1 仙侠样板的改写方向

旧样板是「爽文系统流」：签到开挂、当众打脸、全宗围观。它和成熟作品形态相反：
世界围着主角转，NPC 只负责反应。

改写后为《青云宗 · 签到有债》：

| 维度 | 旧 | 新 |
|---|---|---|
| 标题 | 系统逼我当仙尊 | 青云宗 · 签到有债 |
| 文风 | 爽文仙侠 · 系统流 | 仙侠世界 · 现实后果 · 群像 |
| 系统 | 免费签到外挂 | 签到契：每次签到记一笔债，拿走记忆 / 寿数 / 人情 |
| 主角 | 被迫高调、一路打脸 | 先算代价、只想赎妹妹的杂役 |
| 师姐 | 护短工具人 | 另一个债务人，接近主角是为了评估「转债」 |
| 首席 | 脸谱化反派 | 用规矩做局的既得利益者，动用禁物会反噬自己 |
| 章节 | 打脸 → 更大打脸 | 第一笔 → 人人有账 → 债主上门 |
| 结局 | 系统宣布债主就位 | 主角必须选择：还债、转债，还是让全宗一起查账 |

保留 `TEMPLATE_ID`、角色名、地点名、伏笔 ID、章节 ID 与地图路线，
只重写叙事内容与文风约束，避免破坏既有测试与前端资产页。

## 6. 当前落点

- `src/storyloom/templates/xianxia_system.py`：世界驱动、后果驱动、群像的仙侠样板。
- `src/storyloom/templates/sandbox_life.py`：现代都市开放沙盒的第二套试用模板。
- `src/storyloom/memory/models.py`：`NovelProject` 带 `description`，让作品简介进入运行时。
- `src/storyloom/api/engine.py`：构建 `NovelProject` 时从项目 meta 读取 `description`。
- `src/storyloom/engine/narrative.py`：渲染阶段构造世界书上下文（不含 secrets / 真相）。
- `src/storyloom/crews/scene_crew/crew.py`：`_prose_prompt` 接收 `style / description / world_book`，
  并加入「世界先于主角、NPC 自主、不替玩家决定」的约束。
- `frontend/src/components/GamePanel.vue`：世界状态 tab 增加节拍、在场角色、标记、关系；
  对话流增加舞台指令 chip；行动选项增加序号与类型。
- `docs/DEMO_XIANXIA_SYSTEM.md`：同步改写为新样板剧本。
- 测试断言同步更新（标题、文风、章节标题、导出内容）。

---

## 7. 明确不做

- 不照搬外部作品的视觉与内容市场。
- 不新增第二套前端、独立游戏大厅或作品广场。
- 不在游戏模式里重复创建世界 / 角色。
- 不把 `secrets` 或 `target_revelation` 注入渲染 prompt。
- 不为了「爽感」让导演 Agent 自动放行玩家提案。

---

## 8. 验证

1. `pytest tests/test_templates.py tests/test_templates_integration.py` 通过。
2. 应用模板后，项目标题 / 文风 / 章节标题与新样板一致。
3. 游戏模式进入后，世界状态 tab 能看到节拍、在场角色、标记 / 关系（有数据时）。
4. 渲染 prompt 含作品文风与世界书，但不含任何角色的 `secrets` 或伏笔 `target_revelation`。
5. `npm run test` 中 GamePanel 既有 DOM 断言仍通过。
