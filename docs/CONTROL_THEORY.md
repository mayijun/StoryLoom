# 系统控制论与 StoryLoom

> 本文档整理"钱学森系统控制论如何改进多 Agent 小说系统"这一设计结论。
> 控制不是独立后端模块：调整灵敏度 / 采样 / 闸门本质上就是修改 Flow，
> 配置落点为 `frontend/src/components/flow/controls.ts`。

---

## 1. 先澄清理论定位

钱学森《工程控制论》**并不只是**"单个组件误差大时如何让整体误差小"的单一技巧。
更准确的定位是：

1. **反馈系统优于开环系统**
   > "控制系统的性质常可用某一特定数值是否为零来判断，但若该值不为零但特别小，
   > 很小的误差或噪声干扰就可能导致严重的后果。正因为如此，反馈系统要比开环系统强。"

2. **整体优化而非局部最优**
   > "只追求局部最优而置整体于不顾……这种基于还原论的管理方式，
   > 使得系统的整体优势无法发挥出来，其最好的效果也就是 1+1=2，
   > 弄不好还会 1+1＜2。"

3. **开放的复杂巨系统理论**
   针对规模大、组件众多、难以精确建模的系统，提出
   "以人为主、人机结合，从定性到定量的综合集成法"。

多 Agent 小说系统正好是"组件精度有限、难以单独精确控制"的复杂系统，
因此适用的是**系统方法论**，而不是某个单点技巧。

## 2. 七大原理映射

| # | 原理 | 原文依据 | 系统实现 | 代码位置 |
|---|------|---------|---------|---------|
| ① | 反馈闭环 > 开环 | "反馈系统要比开环系统强" | 生成→批评→修正多轮循环 | Flow `feedback_loop` 节点 |
| ② | 冗余与统计滤波 | "存在噪声时用统计滤波" | 多次采样 + 评分/投票聚合 | Flow `multi_sample` / `nSamples` + `SceneCrew` 一致性投票 |
| ③ | 整体优化 > 局部最优 | "追求总体合理性" | 端到端质量评分与趋势追踪 | `crews/scene_crew/crew.py` |
| ④ | 鲁棒性与灵敏度分析 | "误差传播系数" | 识别高杠杆 Agent 加强校验 | `controls.ts` `AGENT_CONTROL_PROFILES` |
| ⑤ | 解耦/非互相影响控制 | "不互相影响的控制" | 结构化中间格式 + 依赖声明 | `crews/scene_crew/packet.py` `AgentPacket` |
| ⑥ | 分层大系统组织 | "总设计师 + 行政指挥两条线" | Flow 图分层编排 | `frontend/src/components/flow/` |
| ⑦ | 人机结合综合集成 | "以人为主、人机结合" | 关键节点人工审核闸门 | Flow `human_review` 节点 |

## 3. 灵敏度驱动的资源分配

不是所有 Agent 都值得同等的校验成本。误差的"杠杆率"不同：

```
🔴 CRITICAL  director / consistency  → 多次采样 + 投票 / 闭环
🟠 HIGH      protagonist / surprise / foreshadowing → 闭环或多次采样
🟡 MEDIUM    prose                  → 反馈闭环
🟢 LOW       ensemble               → 单次直接通过
```

对应 `AGENT_CONTROL_PROFILES`。控制策略由 `decideControlStrategy`
在 Flow 节点上按角色计算，决定 `ControlDecision`。

---

## 4. 质量闸门与趋势追踪

- **质量闸门**：置信度低于阈值的输出被拦截，防止误差向下游级联。
- **端到端评分**：角色一致性、情节逻辑、意外效果、伏笔融合、文笔质量五个维度，
  以整体分数而非单 Agent 分数作为优化目标。
- **趋势追踪**：连续三个场景质量下降则报警，提示切换更强模型或加强校验。

---

## 5. 核心结论

> 钱学森理论的精髓不是某一个技巧，而是一整套**系统论方法论**。
> 应用到多 Agent 系统中就是：**不追求让每个 AI 完美，而是通过反馈、冗余、
> 解耦、分层的系统设计，让"不完美的组件"组成"足够好的整体"。**
>
> 这正是当前 AI 误差不可忽略的技术现实下，最务实的工程策略。

### 成本与质量的权衡

控制论增强的实验实现曾验证：用约 3 倍 API 调用可以换取明显的质量提升。
该实验实现已移除；M0 只在 `NarrativeEngine` 中保留按角色分级的重试与一致性校验，
未重新引入多采样投票。当前可通过 `src/storyloom/config/model_config.yaml` 的 `strategy.mode` 在
`cost_optimized` / `balanced` / `quality_first` 之间切换。

## 6. 在「双模式基座」中的重新定位

控制论不是作者模式专属，而是整个基座的质量基础设施：

| 原理 | 作者模式 | 游戏模式 |
|---|---|---|
| 反馈闭环 | 一致性检测 → 重试 | 导演 Agent 裁决 → 一致性 → 审核 → 重试 |
| 统计滤波 | 高杠杆 Agent 多次采样 | 关键裁决（攻击/命运收束）多次采样 |
| 灵敏度分析 | 按 Agent 风险分配校验 | 按 `importance_tier` 分配 tick 频率与审核强度 |
| 解耦控制 | 结构化中间格式 | `TurnBoot(text)` / `Fact` / `StageDirective` 三层解耦 |
| 分层管控 | Crew / Flow 编排 | 基座 / 扩展 / 导演 / 表现四层 |
| 人机结合 | `human_review_gate` | 审核不确定、命运收束、关键导演 Agent 裁决转人工 |

新增的三处闭环：

1. **导演裁决闭环**：行动提案 → 规则校验 → 失败给出替代方案 → 重试；
2. **审核闭环**：暂存态 → 审核 → `soften / rewrite / regenerate`，不污染已提交状态；
3. **节奏闭环**：TFC 根据 `drift` / `tension` 调节时间步长，避免主线发散或长期平淡。

### 记忆生命周期也是分层控制

- **分层管控**：`working / short_term / long_term / canon` 对应不同时间尺度的控制层，
  近期高保真、远期高压缩，避免单层上下文膨胀。
- **带滞回的控制**：降级需要同时满足低重要性、长期未命中、无活跃伏笔；
  回温需要连续命中，避免在阈值附近来回抖动。
- **遗忘不是删除**：降级到检索库仍可被召回，相当于把高频缓存换出到冷存储。
- **反馈驱动迁移**：检索命中 → 访问计数 → 回温，形成「使用反馈驱动记忆迁移」的闭环。

对应架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，实施范围见 [MVP.md](MVP.md)。

### M0 的控制论边界

M0 只做**最小闭环**：`retry ≤ N`、schema 校验、超时、硬上限
（`max_turns / max_retries / max_cost`），内化在 `NarrativeEngine` 与导演 Agent 里。
记忆 v2 的压缩 / 降级同样只做最小闭环：阈值触发、确定性兜底、可回温，
不做学习型重要性模型。多采样投票、趋势自适应等高级控制形式不进 M0，只保留接口。
