# 系统控制论与 StoryLoom

> 本文档整理"钱学森系统控制论如何改进多 Agent 小说系统"这一设计结论。

---

## 1. 先澄清理论定位

钱学森《工程控制论》**并不只是**"单个组件误差大时如何让整体误差小"的单一技巧。
更准确的定位是：

1. **反馈系统优于开环系统**
   > "控制系统的性质常可用某一特定数值是否为零来判断，但若该值不为零但特别小，
   > 很小的误差或噪声干扰就可能导致严重的后果。正因为如此，反馈系统要比开环系统强。"

2. **整体优化而非局部最优**
   > "只追求局部最优而置整体于不顾……这种基于还原论的管理方式，
   > 使得系统的整体优势无法发挥出来，其最好的效果也就是 1+1=2，
   > 弄不好还会 1+1＜2。"

3. **开放的复杂巨系统理论**
   针对规模大、组件众多、难以精确建模的系统，提出
   "以人为主、人机结合，从定性到定量的综合集成法"。

多 Agent 小说系统正好是"组件精度有限、难以单独精确控制"的复杂系统，
因此适用的是**系统方法论**，而不是某个单点技巧。

---

## 2. 七大原理映射

| # | 原理 | 原文依据 | 系统实现 | 代码位置 |
|---|------|---------|---------|---------|
| ① | 反馈闭环 > 开环 | "反馈系统要比开环系统强" | 生成→批评→修正多轮循环 | `control/feedback_loop.py` `FeedbackLoop` |
| ② | 冗余与统计滤波 | "存在噪声时用统计滤波" | 多次采样 + 评分/投票聚合 | `StatisticalFilter`、一致性投票 |
| ③ | 整体优化 > 局部最优 | "追求总体合理性" | 端到端质量评分 | `EndToEndEvaluator` |
| ④ | 鲁棒性与灵敏度分析 | "误差传播系数" | 识别高杠杆 Agent 加强校验 | `control/robustness.py` `SensitivityAnalyzer` |
| ⑤ | 解耦/非互相影响控制 | "不互相影响的控制" | 结构化中间格式 + 依赖声明 | `AgentOutput`、`DecouplingValidator` |
| ⑥ | 分层大系统组织 | "总设计师 + 行政指挥两条线" | Orchestrator 分层管控 | `control/hierarchy.py` `SystemOrchestrator` |
| ⑦ | 人机结合综合集成 | "以人为主、人机结合" | 关键节点人工审核闸门 | `human_review_gate` |

## 3. 灵敏度驱动的资源分配

不是所有 Agent 都值得同等的校验成本。误差的"杠杆率"不同：

```
🔴 CRITICAL  director / consistency  → 多次采样 + 投票 / 闭环
🟠 HIGH      protagonist / surprise / foreshadowing → 闭环或多次采样
🟡 MEDIUM    prose                  → 反馈闭环
🟢 LOW       ensemble               → 单次直接通过
```

对应 `SensitivityAnalyzer.PROFILES`。控制策略由 `SystemOrchestrator`
在运行时按角色查询，决定 `ControlDecision`。

---

## 4. 质量闸门与趋势追踪

- **质量闸门**：置信度低于阈值的输出被拦截，防止误差向下游级联。
- **端到端评分**：角色一致性、情节逻辑、意外效果、伏笔融合、文笔质量五个维度，
  以整体分数而非单 Agent 分数作为优化目标。
- **趋势追踪**：连续三个场景质量下降则报警，提示切换更强模型或加强校验。

---

## 5. 核心结论

> 钱学森理论的精髓不是某一个技巧，而是一整套**系统论方法论**。
> 应用到多 Agent 系统中就是：**不追求让每个 AI 完美，而是通过反馈、冗余、
> 解耦、分层的系统设计，让"不完美的组件"组成"足够好的整体"。**
>
> 这正是当前 AI 误差不可忽略的技术现实下，最务实的工程策略。

### 成本与质量的权衡

控制论增强版用约 3 倍 API 调用换取约 37% 的质量提升。
可通过 `config/model_config.yaml` 的 `strategy.mode` 在
`cost_optimized` / `balanced` / `quality_first` 之间切换。
