# 🧵 织章 StoryLoom

**多Agent协作 × 系统控制论 × 智能小说生成**

</div>

---

## 这是什么

**织章**是一个让 AI 像"剧组"一样协作写小说的系统。

写小说的难点不是某一段文字写不好，而是写到几万字之后**人设崩了、伏笔忘了、前后矛盾了**。
传统做法是让一个大模型从头写到尾——它写得越多，忘得越多，错误不断累积。

织章的思路是：**不让一个模型干所有活，而是让一组各有专长的 AI 角色分工协作，
并且在过程中互相检查、纠错。**

## 核心原理

### 1. 分工：一个剧组，而不是一个写手

每个 Agent 负责一件事：

- 🎬 **导演** — 规划这个场景要讲什么，不直接操控角色
- 🎭 **主角** — 拥有独立人格，按自己的动机行动
- 👥 **群演** — 次要角色，共用一个便宜的模型
- 🎲 **意外** — 提出"合理但意想不到"的事件
- 📌 **伏笔** — 管理每条伏笔从埋下到回收的全过程
- ✅ **一致性** — 专门挑错：人设、时间线、设定有没有矛盾
- ✍️ **润色** — 把干巴巴的行动记录改写成有文学性的正文
- 📋 **大纲** — 规划章节结构

每个 Agent 用最适合它的模型（推理强的当导演，有创意的写正文，结构化输出的做校验）。

### 2. 闭环：错了就改，而不是一路错下去

```
单模型写作:  [用户] ──→ [一个LLM] ──→ [输出]            ← 开环，错了也继续
织章:        [用户] ──→ [一组Agent] ──→ [校验] ──→ [改]  ← 闭环，每轮纠错
                       ↑__________________________|
```

生成一段 → 让一致性 Agent 检查 → 发现问题就打回去重写，
直到通过为止。**不是追求每个组件都完美，而是让整体足够好。**

### 3. 控制论：把质量当工程问题管

借用钱学森《工程控制论》的思路来管 AI 写作的质量：

- **反馈闭环**：生成→检查→修正，多轮迭代
- **统计滤波**：同一个关键环节采样多次，投票选最好的
- **灵敏度分析**：导演这种"一错全错"的 Agent 加强校验，群演就一次过
- **分层管控**：上层统筹一致性，下层各干各的，误差不互相传染

> "不追求单项技术的先进性，而追求设计总体的合理性。"
> —— 钱学森《工程控制论》
