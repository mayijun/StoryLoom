# 🧵 织章 StoryLoom

**多 Agent 协作 × 系统控制论 × 动态文字世界**

</div>

---

## 这是什么

**织章**是一个让 AI 像「剧组」一样协作讲故事的系统，目标是成为一个
**动态生成游戏世界的基座**。

它不是让一个大模型从头写到尾——写得越多，忘得越多，人设会崩、伏笔会忘、
前后会矛盾。织章让一组各有专长的 AI 角色分工协作，并在过程中互相检查、纠错；
同时用一个确定性的世界状态层，保证故事不会因为模型的即兴发挥而失控。

## 两种模式

| | 导演模式 | 游戏 / 扮演模式 |
|---|---|---|
| 你 | 作者，安排故事 | 玩家，扮演一个角色 |
| 输入 | 场景 / 章节指令 | 角色行动 / 选择 |
| 权限 | 可以改写世界 | 行动要经过世界裁决，可能失败 |
| 产物 | 小说章节 | 可交互的文字世界 |

两种模式共用同一套世界状态、裁决与扩展机制。模式是存档级运行时状态，
可在任意回合边界切换，世界状态与记忆不重置（切换前自动打 checkpoint）。

## 核心原理

### 1. 分工：一个剧组，而不是一个写手

- 🎬 **导演** — 规划场景意图，不直接操控角色
- 🎭 **主角** — 独立人格，按自己的动机行动
- 👥 **群演** — 次要角色，共享一个便宜的模型
- 🎲 **意外** — 提出「合理但意想不到」的事件
- 📌 **伏笔** — 管理伏笔从埋下到回收的全过程
- ✅ **一致性** — 专门挑错：人设、时间线、设定有没有矛盾
- ✍️ **润色** — 把行动记录改写成有文学性的正文
- 📋 **大纲** — 规划章节结构

### 2. 闭环：错了就改，而不是一路错下去

```
单模型写作:  [用户] ──→ [一个LLM] ──→ [输出]            ← 开环
织章:        [用户] ──→ [一组Agent] ──→ [校验] ──→ [改]  ← 闭环
                       ↑__________________________|
```

### 3. 基座：两条总线，一个世界

```
输入  PlayerIntent   文本 / 选择 / 点击 / 存读档
状态  WorldState     Fact 真相 + Belief 认知 + Memory 经历
输出  StageDirective 对话 / 立绘 / 背景 / 音乐 / 选项
扩展  skill / mod / policy / asset
```

- **LLM 决定「想做什么」，世界规则决定「能不能发生」**；
- 每个角色只看到自己该看到的信息，避免「角色知道全局」；
- 表现层与叙事层解耦：同一段剧情可以输出成文本、ADV、NVL，未来接多模态。

### 4. 扩展：不同玩法选择性导入

| 扩展 | 作用 | 例子 |
|---|---|---|
| `skill` | 知识与文风 | 武侠叙事手册、导演节拍模板 |
| `mod` | 状态与规则 | 地图与旅行时间、好感度、命运、抽奖 |
| `policy` | 审核策略 | 不同地区的合规策略包 |
| `asset` | 图片与音频 | 背景图、BGM、角色立绘 |

时间流速、命运收束、动态角色、内容审核、Galgame 的选项/路线/存档，
全部是可选的扩展，不是写死的核心。

### 5. 记忆：分层、压缩、遗忘

- 核心记忆分层：`working → short_term → long_term → canon`，短期累积到阈值压缩进长期；
- 长期记忆重要性下降、长期未命中且与活跃伏笔无关时，降级到检索库；
- 检索库主要放环境、世界观、角色背景等低命中记忆；命中后可回温；
- 检索后端 `fts / vector / hybrid` 同级可选，默认 `fts`，向量库只是派生索引。

### 6. 控制论：把质量当工程问题管

- **反馈闭环**：生成 → 检查 → 修正
- **统计滤波**：关键环节多次采样，投票选最好的
- **灵敏度分析**：导演这种「一错全错」的角色加强校验，群演一次过
- **分层管控**：上层统筹一致性，下层各干各的，误差不互相传染

> 「不追求单项技术的先进性，而追求设计总体的合理性。」
> —— 钱学森《工程控制论》

## 状态

**作者模式已可用**：项目管理、Agent/Task 可视化配置、资产与场景落库、
章节结构、单场景生成与重跑，以及伏笔状态流转、小说导出（Markdown / TXT）、
成本与质量指标面板、Agent/Task 配置导入导出与跨项目复制。
作者模式使用平铺 `CoreMemory` + Chroma；动态世界使用分层记忆 v2
（`working → short_term → long_term → canon` + archive 按需检索）。

**M0 已交付 — 双模式动态世界纵切（含分层记忆 v2）**：
游戏模式与导演模式共用一条 TurnLoop，跑通「玩家输入 / 导演指令 → GM 裁决 →
演出指令 → 状态更新 → 存档回放」的最小纵切。包含 `FactOverride` 审计回滚、
模式切换 checkpoint、NPC 自主、分层记忆 v2（短期压缩 / 长期 / 常驻 / 降级回温、
按项目落库的记忆配置、`fts / vector / hybrid` 三后端）、Mod v1（YAML）与可玩的游戏前端；
接口按运行时架构预留（async + 超时 + 扩展包隔离），为后续性能扩展留对结构。
验收 A1 ~ A15 由 `tests/test_m0*.py` 覆盖，后端共 **189 个用例全部通过**
（完整清单见 [TESTS.md](docs/TESTS.md)），详见 [MVP.md](docs/MVP.md)。
